# Telegram-бот расписания

Небольшой бот для расписания групп из публичной папки Cloud Mail.

## Что уже умеет

- показывает список групп и сохраняет выбранную группу в SQLite;
- выдаёт расписание на сегодня и завтра;
- читает XLSX с расписанием;
- учитывает изменения из DOCX: замену предмета, преподавателя, кабинета и снятие пары;
- обновляет исходные файлы из Cloud Mail каждые 30 минут;
- может присылать расписание каждое утро — пользователь включает это кнопкой 🔔;
- если Cloud Mail временно не отвечает, использует копии в `data/`.

## Рекомендуемый запуск: Cloudflare Workers

Для варианта «не держать компьютер включённым и всегда принимать сообщения Telegram» используй готовую папку `cloudflare/`. Там Worker работает через webhook, выбранная группа хранится в D1, а расписание обновляет GitHub Actions.

Подробные короткие шаги находятся в [`cloudflare/README.md`](cloudflare/README.md).

## Локальный запуск для проверки

Нужен Python 3.10+.

1. Создай бота у [@BotFather](https://t.me/BotFather): `/newbot` → скопируй токен.
2. В этой папке создай `.env` на основе `.env.example` и вставь токен:

   ```env
   BOT_TOKEN=сюда_токен_от_BotFather
   ```

3. Установи зависимости и запусти:

   ```bash
   python -m venv .venv
   # Windows: .venv\\Scripts\\activate
   # Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt
   python bot.py
   ```

4. Открой бота в Telegram и отправь `/start`.

Токен не добавляй в Git и никому не отправляй. Бот работает через long polling, поэтому для простого запуска достаточно компьютера или VPS, который не выключается.

## Команды

`/start` — начать работу или открыть сохранённую группу  
`/group` — выбрать другую группу  
`/today` — расписание на сегодня  
`/tomorrow` — расписание на завтра  
`/notify` — включить/выключить утреннее уведомление  
`/refresh` — принудительно скачать свежие файлы  
`/help` — помощь

## Запасной вариант без Cloudflare: Render

Для Render используй режим webhook, потому что бесплатный Web Service засыпает после 15 минут без входящих запросов. Telegram будет будить сервис, когда пользователю нужно обратиться к боту. Первый ответ после долгого простоя может прийти с задержкой.

1. Создай пустой репозиторий на GitHub и загрузи туда содержимое этой папки. Файл `.env` и папку `runtime/` не загружай.
2. На [Render](https://render.com/) выбери **New → Web Service**, подключи репозиторий.
3. Выбери Docker и тариф **Free**.
4. Добавь переменные окружения:

   ```env
   BOT_TOKEN=токен_от_BotFather
   BOT_MODE=webhook
   TIMEZONE=Asia/Novokuznetsk
   CLOUD_PUBLIC_URL=https://cloud.mail.ru/public/LQtu/LPPHQ7i4C
   ```

   `WEBHOOK_BASE_URL` можно не добавлять: Render сам передаст адрес сервиса через `RENDER_EXTERNAL_URL`.
5. Нажми **Deploy**. В логах должна появиться строка `Webhook запущен`.
6. Открой бота в Telegram и отправь `/start`.

На бесплатном Render локальная SQLite-база может очиститься после перезапуска сервиса, поэтому выбранная группа иногда может потребовать повторного выбора. Для постоянных утренних уведомлений лучше использовать always-on хостинг; основной функционал бота через Telegram работает в webhook-режиме.

Render официально указывает, что бесплатный Web Service засыпает после 15 минут без входящего трафика и просыпается при следующем HTTP-запросе. Поэтому для этого тарифа используется webhook, а не обычный long polling.

## Развёртывание в Docker

```bash
docker build -t schedule-bot .
docker run -d --name schedule-bot --restart unless-stopped \
  --env-file .env \
  -v "$(pwd)/runtime:/app/runtime" \
  schedule-bot
```

В `runtime/` хранятся база пользователей и кэш скачанных файлов.
